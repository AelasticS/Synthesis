# eer-to-rel-to-text

End-to-end Synthesis showcase: from an EER schema authored in JSX to SQL DDL.

## What this demonstrates

This example composes every major piece of Synthesis in a single Runnable:

1. **Author** a small EER schema in JSX using `@synthesis/standard-metamodels/eer`.
2. **Decide**: build a decision model (`OneToManyStrategy`, `PrimaryKeyStrategy`,
   `NamingConvention`) and bind issues to EER concepts.
3. **Configure**: derive a default configuration model from source + binding.
   The decision model's `NamingConvention` defaults to `SnakeCase`.
4. **Transform** (M2M): the existing `EER2RelDomainWithDecisionTransformation`
   produces a relational schema whose identifiers honor the chosen naming
   convention (`person_id`, `organization_name`, ...).
5. **Render text** (M2T): a small JSX template (`Rel2DdlTransformation`) emits
   `CREATE TABLE` statements into an M2T model, which the engine's `generate`
   runtime serializes to a UTF-8 string.

## Layer-by-layer

| Layer    | File                  | Reuses                                                     |
|----------|-----------------------|------------------------------------------------------------|
| Source   | `source-model.tsx`    | `@synthesis/standard-metamodels/eer`                       |
| Config   | `decision-config.tsx` | `@aelastics/synthesis/metamodels/configuration`            |
| M2M      | `pipeline.ts`         | `eer-to-rel-small/EER2RelDomainWithDecisionTransformation` |
| M2T      | `ddl-template.tsx`    | `@aelastics/synthesis/m2t` M2T runtime                     |
| Pipeline | `pipeline.ts`         | `@aelastics/synthesis/m2t` `generate`                      |
| Runnable | `runnable.ts`         | `@synthesis/runner`                                        |

The transformation logic is **not duplicated**: this folder imports and reuses
`EER2RelDomainWithDecisionTransformation` from `eer-to-rel-small`.

## Sample output

```sql
-- SQL DDL generated by Synthesis from Persons_Relational_Schema_with_Decision_Model

CREATE TABLE person (
  person_id INTEGER PRIMARY KEY AUTOINCREMENT,
  person_name VARCHAR(255)
);

CREATE TABLE organization (
  organization_id INTEGER PRIMARY KEY AUTOINCREMENT,
  organization_name VARCHAR(255)
);

CREATE TABLE works_in (
  organization_id_fk VARCHAR(255) PRIMARY KEY AUTOINCREMENT REFERENCES organization,
  person_id_fk VARCHAR(255) AUTOINCREMENT REFERENCES person
);
```

The default configuration model used by this example picks `JoinTable` for
the 1:N mapping (decision-model default), `UseAutoIncrement` for primary
keys, and `SnakeCase` for naming. Selecting `ForeignKey` instead would
fold the relationship into one of the existing tables. The `VARCHAR(255)`
on FK columns reflects how the upstream EER->Rel transformation derives
column types from role names rather than referenced entity keys; an
improvement noted for a future pass.

```bash
synth example run eer-to-rel-to-text
```
