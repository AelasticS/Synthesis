# Installation

The `synth` CLI is distributed as a self-contained tarball from
[GitHub Releases](https://github.com/AelasticS/Synthesis/releases). The
tarball bundles Node.js and all dependencies; **no separate Node install
is required**.

Two install paths are supported:

1. **[Tarball install](#tarball-install)**: the recommended path for end users.
2. **[Build from source](#build-from-source)**: for contributors and users
   who want the latest unreleased changes.

## Tarball install

### Linux and macOS

Pick the bundle for your platform from the [Download](./download.md) page
(or the
[latest release](https://github.com/AelasticS/Synthesis/releases/latest)),
extract it, and add the resulting `synth/bin` to your `PATH`.

```bash
# Choose one of:
#   synth-v0.3.1-linux-x64.tar.gz
#   synth-v0.3.1-linux-arm64.tar.gz
#   synth-v0.3.1-darwin-x64.tar.gz
#   synth-v0.3.1-darwin-arm64.tar.gz
VERSION=v0.3.1
TARGET=linux-x64         # adjust for your platform
URL="https://github.com/AelasticS/Synthesis/releases/download/cli-${VERSION}/synth-${VERSION}-${TARGET}.tar.gz"

# Download and extract under /usr/local
curl -L "$URL" | sudo tar -xz -C /usr/local

# Add synth to PATH (one-time, pick your shell's rc file)
echo 'export PATH="/usr/local/synth/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

### Windows

Download `synth-v0.3.1-win32-x64.tar.gz` from the [Download](./download.md)
page, then run in PowerShell (no administrator rights needed):

```powershell
# Extract to C:\ (the archive contains a top-level synth folder, so this creates C:\synth)
tar -xzf "$env:USERPROFILE\Downloads\synth-v0.3.1-win32-x64.tar.gz" -C C:\

# Add C:\synth\bin to your user PATH
$userPath = [Environment]::GetEnvironmentVariable('Path', 'User')
[Environment]::SetEnvironmentVariable('Path', "$userPath;C:\synth\bin", 'User')
```

Open a new terminal (restart VS Code for its terminals) and check with
`synth --version`. To install somewhere else, extract to that folder
instead and add its `synth\bin` to `PATH`.

## Build from source

For contributors, or to run the latest unreleased CLI:

### Prerequisites

- **Node.js** ≥ 22: see [nodejs.org](https://nodejs.org/) or use
  [`nvm`](https://github.com/nvm-sh/nvm).
- **pnpm** ≥ 9: see [pnpm.io](https://pnpm.io/installation).
- **Rush** ≥ 5: installed automatically by the build scripts; no manual
  install required.

### Steps

```bash
git clone https://github.com/AelasticS/Synthesis.git
cd Synthesis
node common/scripts/install-run-rush.js install
node common/scripts/install-run-rush.js rebuild

# Link the built CLI as `synth` on your PATH
cd apps/cli
pnpm link --global

synth --version
```

The linked `synth` binary points at `apps/cli/bin/run.js` in your clone,
so any further `rush build` picks up source changes immediately.

To unlink:

```bash
cd apps/cli
pnpm unlink --global
```

## Verifying the install

```bash
synth --version
synth init
synth doctor
```

- `--version` prints the installed CLI version.
- `init` creates the workspace at `~/.synth/` (override with
  `--path <dir>`).
- `doctor` runs a health check against the workspace and reports any
  problems.

In a terminal, `synth` is interactive where it helps: a bare
`synth transformation run` walks you through pickers for the
transformation, the input model, and the configuration consent. Piped,
scripted, `--json`, `--quiet`, and CI invocations never prompt; they fail
with strict, stable errors instead.

## Shell completion

Completion has two layers, set up once for bash or zsh.

**1. Command and flag names**, generated by the CLI:

```bash
synth autocomplete bash     # or: synth autocomplete zsh
```

and follow the printed instructions (they add an `eval` line to your
shell's rc file).

**2. Values**: transformation names, model and configuration refs,
pipeline names, and namespaces, completed context-aware from the workspace
(after `synth transformation run eer-to-relational`, TAB on `--in` offers
only models matching that transformation's source metamodel). This layer is
a wrapper script shipped in the repository at
[`apps/cli/scripts/completion/`](https://github.com/AelasticS/Synthesis/tree/main/apps/cli/scripts/completion)
(`synth.bash` and `synth.zsh`); copy the one for your shell anywhere and
source it from your rc file **after** the autocomplete setup line, so its
registration wins:

```bash
# ~/.bashrc (order matters)
eval $(synth autocomplete script bash)
source ~/path/to/synth.bash
```

On TAB the wrapper asks the CLI itself for the candidate values of the
current position (a fast lookup over manifests and model headers; the
engine is never loaded) and falls back to the command/flag completion when
there are no value candidates. Completion is TAB-triggered only; bash and
zsh are the first-class shells.

## Upgrading

**Tarball install:** delete the extracted `synth` folder and extract the
new version to the same place. `PATH` already points there, so skip that
step. Your workspace at `~/.synth/` is untouched.

**Source install:** `git pull && node common/scripts/install-run-rush.js rebuild`.

## Uninstalling

**Tarball install on Linux and macOS:**

```bash
sudo rm -rf /usr/local/synth
# then remove the PATH line you added to ~/.bashrc (or your shell's rc file)
```

**Tarball install on Windows** (PowerShell):

```powershell
Remove-Item -Recurse -Force C:\synth

# Remove C:\synth\bin from your user PATH
$userPath = [Environment]::GetEnvironmentVariable('Path', 'User')
$kept = ($userPath -split ';') | Where-Object { $_ -and $_ -ne 'C:\synth\bin' }
[Environment]::SetEnvironmentVariable('Path', ($kept -join ';'), 'User')
```

If you extracted somewhere else, use that folder in both places. Windows
PowerShell cannot delete files whose full path is longer than 260
characters; if `Remove-Item` reports "Could not find a part of the path",
delete the folder in File Explorer instead.

**Source install:**

```bash
cd apps/cli && pnpm unlink --global
```

**Workspace.** Uninstalling does **not** remove the workspace with your
installed transformations, models, and pipelines. Delete it if you want
to discard them. It is `~/.synth` unless you chose another folder with
`synth init --path <dir>`:

```bash
rm -rf ~/.synth                                      # Linux and macOS
```

```powershell
Remove-Item -Recurse -Force "$env:USERPROFILE\.synth"  # Windows
```
